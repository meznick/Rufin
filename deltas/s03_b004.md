# Delta Spec: S-03 / B-004

## Context
Video/Classic models have no iOS Trust/pairing step. Removing that step does not make a
mounted volume write-ready. This correction is incorporated in mainline `spec.md` by
`83e0008`; device preflight implementation is still pending. See the [owner decision](research-based-decisions.md)
and [plan FSM](../plan.md#connection-fsm).

## MODIFIED
### S-03 / B-004: readiness preflight
Given a mounted supported Video/Classic iPod and an available backend, when non-mutating
preflight confirms required file access, readable databases, measured capacity,
model/artwork capabilities, and applicable checksum prerequisites, then transition from
Connecting to Ready and enable sync, without pairing.

Given missing Classic FireWire ID, unsupported model/capabilities, denied access, or corrupt
databases, when preflight runs, then show Error with a specific diagnostic/retry option
and keep sync disabled. libgpod owns checksum generation; Video does not require the same
checksum identity as Classic. Missing firmware alone does not prevent readiness (S-06).

### S-05: unavailable backend and removal
Given a mounted iPod but a missing/disabled/incompatible backend, when connection is
attempted, then show Sync unavailable (`BackendUnavailable`) and keep sync disabled without
falling back to copying files. Given a corrected error/backend problem, when retrying,
then return to Connecting and rerun preflight, not directly to Ready.

Given a detected device is removed in any state, when removal is observed, then return to
Disconnected, clear stale device information, and disable sync. Preserve interrupted-operation
reporting/recovery separately (S-12).

## REMOVED
### iOS authorization wait
Given any supported Video/Classic model, when connecting, then never show WaitingForAuth,
Authorization Required, or a Trust prompt. Ordinary filesystem permission failures remain
real errors, not device-pairing requests.

## Verification criteria (implementation pending)
B-004 must test every transition above with disposable fixtures, including mounted-but-not-ready,
missing backend, checksum prerequisites, missing firmware, denied access, retry, and removal.
Finding `iPod_Control` alone must never pass readiness. Real-model write acceptance is B-017.
