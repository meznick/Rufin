# Rebase onto upstream/master (0.19 core) — 2026-11-21

## What happened

`fork-master` was 1120 commits behind upstream `master` (the upstream
ref the repo tracked before was a stale `upstream/main`; the real
mainline is `master`). The fork mainline was rebased linearly onto it
(commit `5c085731`), and the fork's features were ported onto the new
core.

## Upstream changes that forced the port

- The seven GTK crates (gtk-shell/gtk-library/gtk-preferences/
  gtk-widgets/gtk-media-menus/gtk-editors/gtk-player) merged into one
  `ui` crate.
- The library was rewritten: `Database` is gone — a thin `Catalog`
  over a `Store`; favorites/outbox deliveries replaced the old
  favorites write path; `user_media_state` became `user_state`;
  `native_media_state` was dropped; listens/play_counts replaced the
  old stats tables; the schema moved to `migration/steps.rs` with an
  image-based snapshot (`load.rs` positional packing).
- The runtime's catalog-notification flow changed: `feed::Feed`
  replaced the `CatalogRevision` watch channel; `SourceEvent` shrank;
  `SourceNotice` is gone.

## What the port changed (fork surface)

- **Schema 66** (`library`): re-added `native_media_state` +
  `itunes_sync_base` (the iTunes write-back slots), a `native_skip_count`
  tracks column, and a `TRACK_EXPLICIT` flags bit (the explicit flag
  rides the flags column so the positional image load stays intact).
  `NativeUserState` + the catalog merge gain `skip_count`; the merge
  SQL compares skips for tracks only.
- **iTunes storage** (`library/src/itunes.rs`): `Catalog` write/read
  API; user ratings go through `favorites::write_user_media_state`.
- **iTunes source** (`sources/src/itunes`): ported to the
  `Observation` model (`start_observation`/`apply_catalog`; completion
  is the wrapper's). Playback goes through the `Source::stream`
  `Implementation::Itunes` arm, which plays the host path the
  observation stored in `track_details.source_path` — the old
  `ItunesSource::stream(database, …)` is gone. `SourceKind::Itunes`
  added.
- **Runtime** (`rufin-core`): `ItunesSync` runs against the `Catalog`
  and posts `SourceEvent::ItunesLibraryBusy`; the playback hook drops
  the removed `scrobbler.listen_recorded`.
- **UI** (`ui` crate): the iPod page/connection/discovery/sync
  boundary live in `ui::library`; `gtk_widgets::`/`gtk_library::`
  paths resolve to `crate::widgets::`/`crate::library::`; the settings
  screen uses `Shell` + `shell.chrome.window`; the star column and the
  explicit badge follow `TrackPresentation` (`TrackRow.explicit`
  comes from the flags bit). The build-time gtk4-builder-tool
  validation moved into `ui/build.rs`; the dead `ipod_monitor` module
  stays out of the build (the owner's decision — direct
  `IpodConnection` with startup + page-open scans).

## Known follow-ups

- The source-setup grouping (device/remote/server boxes on the
  onboarding page) was reverted to master's flat list — port later if
  wanted.
- The itunes integration gates (`ITL_TEST_PATH`) and the iPod
  connection gates (`IPOD_TEST_*`) skip on hosts without the corpora.
- The D-3 `sync-writes` default flip and the build-flag guard remain
  pending per `b017_plan.md` §8.
